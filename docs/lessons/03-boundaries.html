Lesson 3: only the kernel knows about fibers

Effect v4 keeps its run loop in two files, and Queue, Layer and Stream are built from the public API plus withFiber. peffect does the same, and a lint makes it a rule rather than a habit. The catch in Python: many kernel internals have no underscore (Async, Frame, fiber.stack), so pyright's private-name check can't see them.

Why the allowed list is written down, not inferred. "Fiber methods that return an Effect" would also admit a future unsafe one. The four members are a specification; adding one is a design decision recorded in docs/INVARIANTS.md.
Where it stops. The lint follows names, not values: a Fiber passed to an unannotated helper or stored in a list is invisible to it. Pyright strict forces annotations in src/, which closes most of that gap. A callback it can't inspect (WithFiber(obj.method)) fails the lint instead of passing silently.
How we know it bites. tests/test_boundaries.py marks each forbidden line # expect: B1 and requires exactly those reports; disabling any one check in the lint turns it red.
