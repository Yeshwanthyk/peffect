Lesson 4: services live on the fiber, and come back however the effect ends

A service is looked up by its tag class in the running fiber's context. yield from Users() adds Users to R; provide(Users.context(repo)) takes it out. run only accepts R = Never, so a forgotten service is a type error, not a crash at 3am.

Context({Users: x}, …), class Admins(Users), fiber.context = …refused: no public constructor; concrete tags are final (exact-class lookup); context is read-only
Why tags are final. R is covariant, so pyright would accept a Users context for a program that asks for Admins(Users), but the lookup is by exact class and would miss. Python can't forbid the subclass in the type system, so Tag.__init_subclass__ raises at the class statement.
How we know it holds. tests/test_context.py covers rows C1–C8 in docs/INVARIANTS.md; the interrupt-at-install test requests the interrupt inside the install step and checks the new map was really installed. Removing the restore frame, splitting the install into two steps, or dropping the snapshot copy each turns tests red. The TLA+ kernel model does not cover context; the runtime tests do.
