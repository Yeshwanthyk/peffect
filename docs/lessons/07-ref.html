Mutable state: Ref and SynchronizedRef

A Ref computes and stores a replacement in one synchronous effect step. Use SynchronizedRef when computing the replacement itself runs an effect.

count = yield from Ref[int].make(0)
yield from count.update(lambda n: n + 1)

state = yield from SynchronizedRef[int].make(0)
value = yield from state.update_and_get_effect(
    lambda n: succeed(n + 1)
)
OperationBehavior
Ref.updateRead → compute → assign in one step.
SynchronizedRef.update_effectAcquire permit → read → run callback effect → assign on success → release.
SynchronizedRef.getUnlocked. During a parked update it reads the previous value.

A failure before assignment leaves the slot unchanged. An interrupt may arrive after assignment: an interrupted exit does not guarantee rollback. Mutating the referenced object inside a callback is not rolled back either; use immutable replacement values when that matters.

The permit is not reentrant. Running another synchronized write on the same reference inside its update waits behind itself. Some(None) is a present replacement, not an absent update.

Specify the type parameter on make/make_unsafe. Both classes are invariant because they accept and return values. Python set returns None; the pinned vendor declares void but incidentally returns its backing MutableRef.

Evidence: upstream test ports, source-derived interruption sweeps and two generated models. The model checker for the kernel does not prove these cell contracts. No cross-thread safety is claimed.
